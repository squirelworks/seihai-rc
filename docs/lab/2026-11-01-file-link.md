# Lab note: RC file link, 2026-11-01

Client: `seihai-rc` on this branch (`Session::list_dir`, `get_file`,
`put_file`). No original RC binary was run. No file window was built.

Server: a fake gserver in `tests/file_link.rs`, bound on the loopback
address at an ephemeral port. The gserver-v2 lab pack is not in the agent
environment, so this run does not speak to the fork.

What was done: after a type-6 or type-1 login, the client lists a directory,
fetches a file (including a line feed in the bytes), and sends a file. A
second run asks for a directory list whose name length overruns, a missing
file, a file over 60 KiB, and a put of that same size.

Before: the RC session could log in and list players. It could not list,
fetch or send a world file.

After: `list_dir` returns the names the fake sends, `get_file` returns the
bytes the fake sends, and `put_file` is what the fake records. A malformed
length and a too-large file come back as errors. Payload fields are still a
lab check (`docs/PROTOCOL.md`); the fork was not asked.

Logs: the test binary's stdout from `cargo test --test file_link`. No pcap.
