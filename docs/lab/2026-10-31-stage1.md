# Lab run: stage 1 (login and player list), 2026-10-31

All on loopback in a Linux container. No public servers, no real accounts.

## Setup

- Server: `seihai-gserver-v2`, branch `seihai` at `083306a`, built as in the
  fork's notes (GCC 14, Ninja, `-DUPNP=OFF`). Default world, with the
  listserver and server IPs set to `127.0.0.1`, UPnP off, and two staff
  accounts `labrc` and `labrc2` (copies of the default account with
  `IPRANGE 127.0.0.1`) added to the `staff` option.
- Listserver: the lab listserver v2 (`listserver.py`), open accounts.
- Players: Seihai `squirelworks/seihai` at `bfc912a`, `seihai-mae --version 2.05`
  (headless under Xvfb) and `seihai-ato --version 3.153 --no-window --first-level`.
- RC: this branch, debug build.

## What was run, and what happened

| Command | Result |
|---|---|
| `seihai-rc servers --listserver 127.0.0.1:14922 --account labrc` | Lists `[H] My Server 127.0.0.1:14802`, status text from the listserver |
| `seihai-rc players list --server 127.0.0.1:14802 --account labrc` (gen 5, `GSERV025`) | Logs in; the fork logs `New RC (2.22+)`. Lists the 2.05 player and the other RC |
| same with `--rc classic` (type 1, `GSERV023`) | Logs in; the fork logs `[RC]`. Same list |
| same with `--listserver 127.0.0.1:14922 --pick 1 --tsv` | Picks the server from the RC list, then the same list as TSV |
| `seihai-rc login --account labrc2 --rc classic --for 20` while the others ran | Prints the RC welcome lines, `[online]` for the 3.153 and 2.05 players and each RC login, `[offline]` when they leave |
| `players list` with an account not in `staff` | Exits 1 with `refused: You do not have RC rights.` |

`players list` output with the 2.05 player online:

```
   id  kind    account               nickname              level
    5  rc      labrc2                Watcher
    6  player  test205               default               onlinestartlocal.nw
1 player(s), 1 other RC(s)
```

Before this branch the binary only printed "not implemented yet".

## Seen on the way

- The fork refuses every RC while its listserver link is down; RC logins are
  checked with the listserver.
- After an RC login with an account that is not in `staff` was refused, the
  fork had rewritten that account's file with default values (`IPRANGE 0.0.0.0`,
  `NICK default`). Not an RC bug; worth a look on the fork.
- The fork sends `ADDPLAYER` again when a listed player's props change, so a
  watcher sees `[online]` twice for the same id.
